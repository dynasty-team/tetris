# Decision Log


| การตัดสินใจ | สิ่งที่เลือกใช้ | เหตุผล / Trade-off |
|---|---|---|
| Lock Delay | ใช้ Lock Delay ก่อนที่ชิ้นส่วนจะถูกล็อกลงบนกระดาน | เพื่อให้ผู้เล่นยังมีเวลาขยับหรือหมุนชิ้นส่วนหลังจากแตะพื้น ทำให้ควบคุมชิ้นส่วนได้ง่ายขึ้น แต่ต้องจำกัดเวลาไว้เพื่อไม่ให้ผู้เล่นยื้อชิ้นส่วนได้นานเกินไป |
| 7-Bag Randomizer | ใช้ระบบ 7-Bag Randomizer | เลือกใช้เพื่อให้ Tetromino ทั้ง 7 แบบออกกระจายมากขึ้น ลดโอกาสที่ชิ้นเดิมจะออกซ้ำบ่อยเกินไป และช่วยไม่ให้บางชิ้นหายไปนานเกิน |
| Pause Handling | หยุดการตกของชิ้นส่วนตอน Pause และเก็บสถานะเกมเดิมไว้ | เมื่อกด Pause เกมจะหยุดชั่วคราว แต่คะแนน ตำแหน่งของบล็อก และสถานะต่างๆ จะยังอยู่เหมือนเดิม เมื่อกด Resume เกมก็สามารถเล่นต่อจากจุดเดิมได้ |
| Save Timing | บันทึก High Score ตอน Quit หรือ Game Over | เนื่องจากระบบนี้ใช้เก็บคะแนนสูงสุดเป็นหลัก จึงไม่จำเป็นต้องบันทึกสถานะเกมตลอดเวลา และช่วยลดการเขียนไฟล์ที่ไม่จำเป็น |
| Game Resume | ไม่รองรับการเล่นต่อจาก Save | ตอนนี้ระบบยังไม่ได้บันทึกสถานะเกมทั้งหมด เช่น กระดาน ชิ้นส่วนที่กำลังเล่น คะแนน เลเวล และข้อมูลการสุ่มชิ้นส่วน จึงกำหนดให้บันทึกเฉพาะ High Score เพื่อป้องกันไม่ให้โหลดเกมกลับมาแล้วข้อมูลไม่ตรงกับสถานะจริง |
| Top Boundary & Lock-Out | ตรวจสอบขอบบนของกระดานและกำหนด Game Over เมื่อชิ้นส่วนอยู่ในตำแหน่งที่เล่นต่อไม่ได้ | ป้องกันไม่ให้ชิ้นส่วนหลุดออกนอกพื้นที่ของกระดาน ช่วยกำหนดเงื่อนไข Game Over ให้ชัดเจนเมื่อพื้นที่ด้านบนเต็มจนเล่นต่อไม่ได้ |
| Board Dimension Validation | ตรวจสอบว่ากระดานมีขนาด 10 × 20 | เพื่อให้ขนาดกระดานตรงกับข้อกำหนดของเกม และป้องกันปัญหาที่อาจเกิดขึ้นจากการใช้กระดานที่มีจำนวนแถวหรือคอลัมน์ไม่ถูกต้อง |
